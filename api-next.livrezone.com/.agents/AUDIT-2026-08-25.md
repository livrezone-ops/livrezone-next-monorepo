## INCIDENT RÉSOLU — Communication code-server ↔ Meilisearch (27 août 2026)

Rapport technique complet : `C:\Users\fsts\Downloads\solution_meilisearch_code_server.txt` (archive locale à conserver).

**Chronologie :**
1. Les tests lancés depuis `code-server` se bloquaient (~131 s par appel) sur les synchros Scout : `cURL error 28` vers `192.168.1.202:7700`. Deux fichiers bloqués : `AdminPauseSubscriptionTest`, `CartMergeClampTest`.
2. Diagnostic correct (GPT 5.6) : Meilisearch tourne sur le **daemon Docker système**, attaché au réseau partagé `code-server-docker_default` → joignable par DNS interne sous le nom `meilisearch` (health OK en 0,001 s). L'adresse LAN `192.168.1.202:7700`, elle, est filtrée/injoignable depuis ce réseau.
3. La correction appliquée a modifié la ligne `MEILISEARCH_HOST` du `.env` → **effet de bord immédiat en prod** (`GET /api/books` HTTP 500) car le `.env` est unique et lu à chaud par le container rootless `php-fpm-8.5`, qui ne résout pas le DNS `meilisearch`.
4. Rétablissement prod : `MEILISEARCH_HOST=http://192.168.1.202:7700` (valeur éprouvée pour le contexte rootless). Vérifié HTTP 200.
5. Solution retenue : override d'environnement réservé aux tests, aucun fichier persistant modifié :

```bash
docker exec -e MEILISEARCH_HOST=http://meilisearch:7700 \
  -w /workspace/api-next.livrezone.com code-server \
  php vendor/bin/phpunit -c phpunit.xml
```

→ Suite complète verte **avec le vrai moteur Meilisearch** : 66 tests / 205 assertions en 4,4 s.

**Règles à retenir :**
- ⚠️ Le `.env` est un fichier partagé entre 2 contextes réseau (daemon système ↔ daemon rootless) : toute valeur réseau y est **globale**. Adapter un contexte = passer par des overrides d'environnement, jamais éditer le `.env`.
- Les créations/modifications de données n'endommagent **jamais** Meilisearch : synchro Scout échouée = simple trace log + index rafraîchi plus tard via `scout:import`. Seule une config réseau erronée coupe la recherche.
- Sécurité (reporté) : port `7700` publié sur `0.0.0.0` avec Master Key actif → limiter par firewall dès que possible.
