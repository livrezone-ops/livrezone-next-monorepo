# WORKFLOW

Toujours suivre cet ordre :

1. Lire le besoin.
2. Analyser l'existant.
3. Identifier les fichiers impactés.
4. Proposer un plan.
5. Attendre la validation implicite du plan ou poursuivre selon les instructions.
6. Implémenter par petites étapes.
7. Lancer build + tests.
8. Corriger les erreurs.
9. Vérifier les régressions.
10. Résumer les changements effectués.

Règle d'or :

Ne jamais modifier plus que nécessaire.
