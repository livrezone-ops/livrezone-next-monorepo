SECTION 0 — CONTEXTE ET RÈGLES NON NÉGOCIABLES
--------------------------------------------------------------------------------
R0.1  Les notifications INTERNES (in-app / canal database) sont TOUJOURS
      actives : aucun utilisateur ne peut les désactiver, aucun toggle ne
      les mentionne dans l'UI, et la préférence historique (book_orders,
      in_app) n'est plus consultée par ProcessBookOrderNotifications.
R0.2  La messagerie interne (chat) n'est PAS un canal de notification.
      Aucun envoi automatique dans le chat (aucun ->notify() ne cible le
      chat ; ChatMessage/ChatThread restent exclusivement réservés aux
      échanges entre utilisateurs). Le digest (T3) est une notification
      ENVOYÉE À l'utilisateur, jamais écrite DANS le chat.
R0.3  Évolutivité : tout nouveau type de notification = 1 entrée dans
      App\Services\NotificationTypeService::FILTERABLE (+ 1 ligne de miroir
      front lib/notifications.ts NOTIFICATION_TYPE_LABELS). Aucune refonte.
R0.4  Canaux par abonnement : source unique =
      SubscriptionService::allowedNotificationChannels(Profile)
        - Premium : mail + database + telegram (toujours)
        - Pro     : database + telegram SI l'admin a activé le réglage
                    'telegram_pro_enabled' (défaut : désactivé)
        - Free    : database uniquement
      WhatsApp : réservé au type book_orders (notifications de demandes de
      livres uniquement — décision validée), non soumis à l'abonnement
      (garde-fous existants has_whatsapp + numéro conservés).
R0.5  Réglages admin : n'ajouter une clé QUE via la chaîne complète
      SubscriptionService::EDITABLE_SETTINGS (clé => ENV de repli)
      + getEditableSettings() + règle de validation updateSettings
      (AdminController) + UI admin. Écritures en POST uniquement (WAF).
R0.6  Toute la UI est en français, style existant (violet #6D28D9, rounded-xl,
      font-bold, Tailwind). Toast au lieu d'alert(). Composants React définis
      au niveau module (règle React Compiler), setState jamais appelé
      directement dans un useEffect (callback async uniquement).
