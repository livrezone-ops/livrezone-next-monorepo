## 1. Index Meilisearch `books` — réparation + garde-fou

- **Constat 09/09 matin** : index `books` réduit à ~35k docs sur 2 champs (`{id, authors_list}`) — 3ᵉ incident du même type (04-05/09, 07/09 01:32-01:42). Pages `/books` et rayons vides ou erronées.
- **Cause racine confirmée** : scripts ponctuels de correction de noms d'auteurs qui POSTent des documents partiels directement sur Meili (rappel : `POST /indexes/books/documents` **remplace** le document entier, il ne fusionne pas).
- **Réparation** : réimport complet via Scout (`Book::…->searchable()`) — 697 172 docs × 12 champs vérifiés via `fieldDistribution` ; recette passée : JEUNESSE 92 167, ROMANS 117 884, facettes sous-thèmes, `sort=recent`, ISBN exact (`field=isbn`), recherche auteur, 35 facettes catégories.
- **Garde-fou** : `app/Console/Commands/BooksMeiliHealthCheck.php` (`php artisan books:check-meili`) — compare `fieldDistribution` aux 12 champs attendus + drift du compte de documents ; `Log::critical` en cas d'écart ; planifié quotidiennement 03:45 (`routes/console.php`).
- **Règle d'or** (consignée dans le doc incident) : corriger MySQL puis réindexer via Scout — **jamais** de POST direct sur Meili.

## 2. Sitemap éditeurs — erreur « items over 2MB » (build Next)

- `/sitemap-editeurs.xml` faisait échouer le build : l'entrée data cache Next.js est plafonnée à 2 Mo (47 690 éditeurs en une réponse).
- **Correctif** : `getPublishersAll()` (`lib/books-api.ts`) pagine à 10 000/page (cap 20 pages) et agrège ; `app/sitemap-editeurs.xml/route.ts` mis à jour.

## 3. UX recherche catalogue (décision propriétaire 09/09)

- **Retrait** du « Entrée = 1ʳᵉ suggestion » (posé puis reverté le même jour — l'utilisateur garde la main).
- **Nouvelle UX** : Entrée = recherche globale titre + auteur + ISBN → page de résultats complète ; si la saisie est un **ISBN valide présent exactement une fois** au catalogue → **ouverture directe de la fiche** (fast-path `field=isbn`, endpoint existant, **API inchangée**).
- **Appliqué aux 3 points d'entrée** : vitrine `/books` (`BooksHome`), vue recherche/filtres (`BooksClient`), hero des rayons (`BookThemeSearch` — le match ISBN exact ouvre la fiche même hors rayon, correspondance à 100 %).
- **Nouveaux modules** : `lib/isbn.ts` (`isbnQuery()` : normalisation tirets/espaces, validation checksum ISBN-13 préfixe 978/979, conversion ISBN-10 → ISBN-13) ; `lib/books-search.ts` (`findExactIsbnBook()` partagé). Testés sur ISBN réels du catalogue (Clean Code 0132350882 → 9780132350884, Harry Potter 0747532699 → 9780747532699, suffixe X, checksum invalides rejetés).
